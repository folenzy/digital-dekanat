# Журнал процесса: как «На связи» делали вместе с ИИ

Ведётся по ходу работы. Формат записи: **что сделали → инструмент, скилл, субагент → ключевой промпт → что пошло не так → что сделал человек**.
Модели: этап 0 — Claude Sonnet 5.5 (`claude-sonnet-5-5`), начиная с этапа 1 — Claude Opus 5.5 (`claude-opus-5-5`), обе в Claude Code (десктоп-приложение, Windows).

## 2026-11-07

### 0. Постановка задачи и мастер-промпт
- **Человек:** вставил полный текст ТЗ конкурса и попросил: «Составь промт, как сделать этот проект, использовать можно и нужно скиллы, которые я загружал».
- **Скилл:** `superpowers:brainstorming`. Вместо того чтобы сразу писать промпт, ИИ пересказал задачу и задал главный открытый вопрос: где хостить, ведь ТЗ требует доступ из России без VPN.
- **Человек:** «У меня нет хостинга, надо бы придумать бесплатный или очень дешёвый вариант».
- **Исследование (WebSearch, 3 запроса):** бесплатный хостинг для Node/Python, доступный из РФ; блокировки Vercel, Netlify, Cloudflare и Render в РФ; дешёвые российские VPS.
  - Вывод: у Vercel есть сообщения о блокировке IP в РФ, у Netlify открытая тема на форуме, Cloudflare в РФ замедляют. Российский VPS стоит около 200–300 ₽/мес (по обзорам Beget, Timeweb).
  - ИИ отдельно отметил, что цены взяты из обзоров и их нужно сверить на сайтах провайдеров.
- **Человек выбрал:** российский VPS.
- **Результат:** мастер-промпт `prompts/00-master-prompt.md`: роль, порядок скиллов, требования ТЗ, безопасность, идеи, этапы 0–7, журнал процесса, критерии готовности.
- **Человек:** уточнил «вымышленный вуз», ИИ поправил промпт.

### 1. Запуск по промпту и брейншторм
- **Человек:** переключил модель на Opus 5.5 (`/model`) и написал: «Сделай проект чисто по промту, который ты написал, мега внимательно».
- **Проверка окружения (ИИ):** Node 24, npm, git, Docker есть; Python нет, поэтому Playwright берём для Node.
- **Брейншторм, вопросы по одному** (`superpowers:brainstorming`):
  1. *ИИ:* что больше всего раздражает в общении с деканатом? → *Человек:* «непонятно, куда писать, чтобы информация дошла до деканата, тяжело списаться, долгие ответы». Это стало главной идеей кабинета: «деканат, до которого можно достучаться».
  2. *ИИ:* по каким вопросам чаще пишешь? → *Человек:* справки, учебные вопросы, стипендия. Отсюда три темы обращений и маршрутизация по отделам.
  3. *ИИ:* помощник с настоящей нейросетью (нужен ключ) или поиск по базе ответов? → *Человек:* «пока без неё». Нейросеть оставлена как точка расширения.
  4. *ИИ:* до какого числа сдавать? → *Человек:* до 25 ноября, но сделать быстрее и потом доводить. Работа разбита на две волны.
  5. *Человек:* «подумай, что можно добавить для вау-эффекта». *ИИ* предложил 5 идей, отсортированных по силе эффекта (деканат пишет первым, ответ в реальном времени, справка с QR, табло прозрачности, запись на приём). Человек доверил выбор ИИ: в волну 1 пошли первые две.
  6. **Визуальный компаньон:** ИИ поднял локальный сервер (скилл brainstorming, `start-server.sh`) и показал один экран «Сегодня» в трёх стилях. Человек выбрал **A «Бумага»**. Макет: `docs/design/mockups/01-visual-style-options.html`.
  7. Название: ИИ предложил «На связи» и «Университет Ориентир», человек согласился.
  8. Стек: ИИ показал 3 подхода с плюсами и минусами (Next.js + PostgreSQL / отдельный API + SPA / Next.js + SQLite). Человек выбрал A. Решение записано в `docs/adr/0001-stack.md`.
- **Ручные шаги человека:** выбрал папку проекта (Загрузки), ИИ создал в ней `digital-dekanat`.

### 4. Реализация: субагенты
- **Человек выбрал** выполнение через субагентов (скилл `superpowers:subagent-driven-development`), ветка `feat/volna-1` (предложена ИИ, подтверждена человеком в карточке).
- **Схема работы:** главный агент (контроллер, Opus 5.5) не пишет код сам. На каждую задачу он запускает нового субагента-исполнителя с коротким брифом (текст задачи из плана, файлом), а после него отдельного субагента-ревьюера, который проверяет соответствие спеке и качество кода. Если есть замечания, исполнитель их исправляет, и ревьюер проверяет снова.
- **Модели по ролям** (экономия без потери качества): механические задачи и обычные ревью — Sonnet 5.5; вход и безопасность, обращения, интерфейс — Opus 5.5; финальное ревью всей ветки — Opus 5.5.
- **Предварительная проверка плана** нашла 7 противоречий между задачами. Примеры: задача 3 хеширует пароли раньше, чем задача 4 создаёт функцию хеширования; e2e-тест задачи 10 требует страниц, которые появляются только в задачах 12–14. Все решения записаны: функции перенесены в более раннюю задачу, порядок выполнения изменён на 1–9, 11–14, 10, 15–17.
- **Журнал выполнения** `.superpowers/sdd/…/progress.md` позволяет продолжить с нужного места, даже если контекст ИИ сожмётся.
- **Шаблоны** для исполнителя и ревьюера контроллер вынес в файлы, чтобы каждый запуск был коротким: «прочитай инструкции, бриф, ограничения».

## 2026-11-12. Полировка интерфейса после показа друзьям

## 2026-11-14. Длинная очередь сотрудника: группы по сроку и «Взять следующее»

- **Откуда задача.** Проверка худшими данными показала: при 200 новых обращениях очередь рендерит все строки, страница вытягивается примерно на 10 000 px. Человек спросил, как это обыграть.
- **Решение ИИ, одобрено человеком («делай»).** Обычную постраничную разбивку «1, 2, 3 …» ИИ отверг: она решает техническую проблему длинной страницы, но не задачу сотрудника — тот не листает очередь, а ищет, что горит, и берёт следующее. Вместо неё:
  - **группы по сроку** — «Просрочено», «Сегодня», «Завтра», «Позже», границы — полночь по Москве. В группе до 10 строк и ссылка «Показать все N»; «Сегодня» показывается целиком — это то, что горит. Состояние в адресе (`?show=overdue`), работает без JavaScript;
  - **«Взять следующее обращение»** — единственная синяя кнопка экрана. Сервер сам выбирает самое срочное новое обращение в отделах сотрудника (с учётом фильтра отдела), берёт его в работу и открывает. Это электронная очередь настоящего деканата: брать по порядку, а не выискивать глазами;
  - **предел на сервере**: каждая группа — диапазон срока, выбирается своим запросом с `limit` по готовому индексу (отдел, статус, срок); итоги — одним запросом-счётчиком. Счётчики вкладок теперь тоже один запрос — раньше страница ради четырёх чисел загружала все четыре списка целиком.
- **Двое нажали одновременно.** Выбор и запись — в одной транзакции, строка выбирается с `FOR UPDATE SKIP LOCKED`: обращение, которое прямо сейчас берёт коллега, пропускается, и второй получает следующее, а не ошибку. Если брать уже нечего — понятное сообщение «Новых обращений нет — всё разобрано» (новый код отказа `empty`). Перед реализацией ИИ сверил по типам Drizzle 0.45, что `skipLocked` вместе с `of` поддерживается, а не полагался на память.
