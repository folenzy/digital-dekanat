# Инструменты, IDE и сервисы

Полный перечень того, чем делали «На связи», и зачем. Хронология — в `LOG.md`, итог — в `DESCRIPTION.md`.

## ИИ-ассистент и модели

| Инструмент | Для чего |
|---|---|
| **Claude Code** (десктоп-приложение, Windows 11) | Единственный ИИ-ассистент проекта: исследование хостинга, брейншторм, спецификация, план, весь код, тесты, деплой-файлы, документы. IDE отдельно не использовалась: код писал и правил ассистент, человек принимал решения и одобрял шаги |
| Модель **Claude Sonnet 5.5** (`claude-sonnet-5-5`) | Этап 0 (исследование хостинга, мастер-промпт); позже — исполнитель механических задач и ревьюер большинства задач |
| Модель **Claude Opus 5.5** (`claude-opus-5-5`) | С этапа 1: брейншторм, спека, план, контроллер выполнения; исполнитель задач про безопасность, обращения и интерфейс; ревьюер задач 4, 6, 10 |

В самом продукте нейросеть не вызывается (решение пользователя «пока без неё»); помощник «Спроси деканат» — полнотекстовый поиск PostgreSQL. В `.env.example` оставлен зарезервированный `LLM_API_KEY` (сейчас кодом не читается; когда появится — только на сервере).

## Скиллы (наборы инструкций для ассистента)

| Скилл | Где и зачем использован |
|---|---|
| `superpowers:brainstorming` | Этапы 0–1: вопросы по одному, 3 подхода к стеку, выбор стиля через визуальный компаньон, дизайн-документ `docs/specs/…` и его проверка субагентом |
| `superpowers:writing-plans` | Этап 3: план из 17 задач с точными файлами, сигнатурами, тестами и командами проверки (`docs/plans/…`) |
| `superpowers:subagent-driven-development` | Этап 4: контроллер раздаёт задачи субагентам-исполнителям и ревьюерам, ведёт журнал выполнения, решает спорные вопросы |
| `superpowers:test-driven-development` | Каждая задача исполнителя: сначала падающий тест (RED), потом код (GREEN); в отчётах — команды и вывод. Где тесты писали после кода (задачи 5, 9), это честно отмечено: в задаче 5 силу тестов доказали мутацией, в задаче 9 исполнитель прямо признал, что фазы RED не было |
| `superpowers:systematic-debugging` | Нестабильный тест лимитов: воспроизведение (4 падения из 15), причина, красный тест на точный счёт, исправление блокировкой, мутационная проверка |
| `frontend-design` | Задача 11 (дизайн-система «Бумага», логотип, оболочка) и экраны задач 12–14 |
| `webapp-testing` | Задача 15: сквозные сценарии Playwright, IDOR через повтор настоящих server actions, axe, 360 и 1280 px |
| `security-review` | Задача 17: итоговое ревью ветки. Скилл упал при запуске (нет удалённого `origin`), ревью проведено по его методике вручную — `SECURITY-REVIEW.md` |
| `superpowers:verification-before-completion` | Перед каждым «готово»: полный прогон `npm test`, e2e на свежей сборке, `tsc`, `eslint`, `npm run build` с выводом в отчёте |

## Субагенты

Главный агент (контроллер, Opus 5.5) код не писал: на каждую задачу запускал свежего субагента-исполнителя с коротким брифом, затем отдельного субагента-ревьюера. Замечания ревью уходили тому же исполнителю (раунд исправлений), затем — повторное ревью.

| Роль | Модель | Сколько раз | Что делал |
|---|---|---|---|
| Builder check спеки (general-purpose) | запущен из сессии Opus 5.5 | 1 | Читал спеку глазами исполнителя, нашёл 4 места, где пришлось бы угадывать (главное — общие демо-аккаунты устаревают) |
| Исполнитель | Sonnet 5.5 | 8 задач (1, 2, 3, 5, 7, 8, 9, 15) + волна итоговых исправлений | Каркас, схема, демо-мир, чтение данных, правила, поиск, realtime, e2e; после итогового ревью — правки по его замечаниям |
| Исполнитель | Opus 5.5 | 10 задач (4, 6, 10, 11, 12, 13, 14, исправление лимитов, 16, 17) | Вход и сессии, обращения, CSP, дизайн и экраны, отладка гонки, деплой, итоговые документы |
| Ревьюер (первичное ревью) | Sonnet 5.5 и Opus 5.5 (задачи 4, 6, 10) | 18 (задачи 1–17 и исправление лимитов) | Соответствие спеке и качество кода, поиск дыр |
| Ревьюер (повторное, после исправлений) | Sonnet 5.5 | 6 | Проверка, что замечание закрыто и ничего не сломано |
| Ревьюер (итоговое, вся ветка) | Opus 5.5 | 1 | Сквозная проверка всей ветки перед сдачей; замечания закрыла волна итоговых исправлений |

Шаблоны промптов исполнителя и ревьюера — `prompts/02-implementer-template.md`, `prompts/03-reviewer-template.md`.

## Проверка и тесты

| Инструмент | Для чего |
|---|---|
| **Vitest** 5 | Юнит- и интеграционные тесты серверного слоя на настоящей PostgreSQL (IDOR, лимиты с параллельными запросами, правила «Деканат пишет первым», SLA, время по МСК) |
| **Playwright** (Node) | Сквозные сценарии на продакшен-сборке, 360 и 1280 px, проверка «в консоли нет ошибок», заголовки безопасности, IDOR и CSRF через повтор настоящих server actions, скриншоты |
| **axe** (`@axe-core/playwright`) | Доступность 11 страниц: нашёл 3 реальных нарушения, их исправили |
| Тест контраста WCAG (свой, Vitest) | Считает контраст по цветам из `tokens.css`; поймал недостаточный контраст серого и терракотового текста |
| TypeScript `tsc --noEmit`, ESLint | Типы и линтер перед каждым коммитом |
| Встроенный браузер Claude Code | Просмотр макетов визуального компаньона и скриншотов |
