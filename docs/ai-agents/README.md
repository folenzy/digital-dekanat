## `volna-1/` — выполнение плана субагентами (7–10 ноября)

Главный агент (контроллер) сам код не писал: на каждую задачу запускал свежего исполнителя с коротким брифом, затем отдельного ревьюера. Всё, что они передавали друг другу, — здесь.

| Файл | Что это |
|---|---|
| [`global-constraints.md`](volna-1/global-constraints.md) | Общие правила, которые получал **каждый** субагент: вымышленные данные, `now: Date` во всех функциях времени, `studentId` только из сессии, секреты не читать, сверять API Next 16 с документацией, а не с памятью; окружение; **решения контроллера по противоречиям между задачами**, найденным до начала кода |
| [`implementer-instructions.md`](volna-1/implementer-instructions.md) | Как работает исполнитель: если в брифе что-то неясно — сразу `NEEDS_CONTEXT` с вопросами, «не угадывать»; тест вперёд с доказательством падения (RED → GREEN); отчёт в файл и короткий ответ со статусом `DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT` |
| [`reviewer-instructions.md`](volna-1/reviewer-instructions.md) | Как работает ревьюер: «не доверяй отчёту» — каждое утверждение исполнителя сверяется с diff; весь набор тестов не перезапускать, точечный тест — только при конкретном сомнении; у каждой находки `file:line` и уровень Critical / Important / Minor |
| `task-N-brief.md` | Бриф задачи N от контроллера исполнителю: файлы, интерфейсы, тесты, критерии готовности |
| `task-N-report.md` | Отчёт исполнителя: что сделано, какие тесты, что осталось спорным. В нескольких отчётах исполнители **сами признают** отступления (тесты написаны после кода, оспоренное замечание ревью) |
| [`task-fix-limits-*.md`](volna-1/task-fix-limits-report.md) | Внеплановая задача: разбор нестабильного теста лимитов до причины и исправление транзакционной блокировкой |
| [`progress.md`](volna-1/progress.md) | Журнал контроллера: проверка плана до начала (таблица противоречий и решений), какая модель на какой задаче, вердикты ревью, раунды исправлений |
| [`final-fix-report.md`](volna-1/final-fix-report.md) | Волна исправлений после итогового ревью всей ветки |

Исходные файлы лежали в служебной папке `.superpowers/` (исключена из git, её создают скиллы). Сюда скопированы все, кроме срезов `git diff` для ревьюеров: они повторяют историю коммитов. Перед публикацией файлы проверены на секреты: встречаются только имена переменных (`DEMO_RESET_TOKEN`, `POSTGRES_PASSWORD`), значений нет; адрес `postgres://admin:topsecret@db.example.com` — нарочно выдуманный, из теста защиты сброса.

**Подписи в коммитах.** По правилу из `global-constraints.md` субагенты заканчивали каждый коммит строкой `Co-Authored-By: Claude <модель>` — чтобы по истории было видно, какая модель реально писала код. После волны 1 автор попросил коммиты без таких подписей; поэтому поздние коммиты их не содержат.
