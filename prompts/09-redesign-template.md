# 09. Редизайн «чтобы не было похоже на нейросеть»: промпт-шаблон автора в пять этапов

**Этап:** редизайн всего кабинета, 13–14 ноября.
**Функция:** заставить ИИ проверить собственную работу на «признаки ИИ» и переделать интерфейс по референсам, с остановками на решения человека.
**Скиллы:** `refero-design` (методика), `frontend-design`, `remove-animations`, `break-ui`, `web-design-guidelines`, `webapp-testing`.
**Модель:** этапы 1–4 — Claude Fable 5.2; с проверки этапа 5 автор переключил модель на Claude Opus 5.5 (`/model`).
**Источник:** `docs/process/LOG.md`, записи «Редизайн всего кабинета» и «Редизайн „Ведомость“: реализация и проверка»; итог — `DESIGN.md`.

## Промпт автора (дословно)

```text
Ты ведущий продуктовый дизайнер с 15 годами опыта. Задача: переработать [страницу/экран, например «список студентов»] проекта так, чтобы он выглядел как работа живого дизайнера, а не нейросети. «Красиво» недостаточно: нужен интерфейс с характером, под реальную задачу и реальных пользователей.

КОНТЕКСТ
Продукт: [что это]. Пользователи: [кто, как часто, на каком устройстве]. Тон: [например: спокойный, деловой, без пафоса]. Ограничения: [стек, что нельзя менять].

ЭТАП 1. ИССЛЕДОВАНИЕ (код не писать)
1. Вызови /refero-design и через Refero MCP найди 4-6 реальных референсов (стили, экраны, flows) для продукта такого типа. Не бери референсы из общей «красивой» выдачи, бери близкие по задаче.
2. По каждому выпиши конкретно: что берём (типографика, плотность, сетка, цвет, навигация, состояния) и что не берём.
3. Покажи текущий экран (скриншот через браузер) и честно назови 5-7 признаков «сделано ИИ»: одинаковые карточки, градиенты, лишние тени и скругления, один фиолетовый акцент, пустые заголовки, иконка в каждом пункте и т. п.
4. Предложи 2 разных направления с обоснованием и порекомендуй одно.
ОСТАНОВИСЬ и жди моего выбора.

ЭТАП 2. СИСТЕМА РЕШЕНИЙ
После моего ответа зафиксируй в DESIGN.md: шрифты (пара с причиной выбора), шкалу размеров, палитру (нейтральные + 1 акцент с ролью, максимум 1-2 исключения), отступы, радиусы, тени (или их отсутствие), правила плотности. Каждое решение связано с референсом или задачей пользователя. ОСТАНОВИСЬ на согласование.

ЭТАП 3. РЕАЛИЗАЦИЯ
Используй /frontend-design для характера и /shadcn для компонентов (если в проекте есть components.json). Правила:
- Иерархия вместо равных блоков: главное действие заметнее, остальное тише.
- Плотность по задаче: таблицы и фильтры для рабочего интерфейса, а не карточки ради красоты.
- Реальный текст: подписи, ошибки, пустые состояния как в живом университете, без «Добро пожаловать» и «Управляйте эффективно». Реальные данные в примерах (разной длины ФИО, группы, даты).
- Без: градиентных фонов, стеклянных эффектов, декоративных иконок в каждом пункте, лишних теней, скруглений «на всё», эмодзи вместо иконок.
- Неидеальная симметрия там, где она оправдана: выравнивание по сетке, а не «всё по центру».
- Состояния: hover, focus, active, disabled, loading, пусто, ошибка. Все продуманы.

ЭТАП 4. ЖИВЫЕ ДЕТАЛИ
/emil-design-eng и /animate: переходы, отклик на нажатие, плавность. Только там, где это помогает понять интерфейс. Лишнюю анимацию убери через /remove-animations. Учитывай prefers-reduced-motion.

ЭТАП 5. ПРОВЕРКА
1. /break-ui: ломаем худшими данными (очень длинные ФИО, пустые списки, 0 и 10000 записей, чужие алфавиты).
2. /web-design-guidelines: аудит доступности и UX, исправь замечания.
3. /webapp-testing или встроенный браузер: скриншоты на 375, 768 и 1440 px, светлая и тёмная тема, если есть. Смотри глазами и опиши, что не так.
4. Пройдись по списку «признаков ИИ» из этапа 1 и честно отметь, какие остались.

ОТЧЁТ
В конце: что изменено и почему (со ссылкой на референс), что проверено и как, что НЕ проверено. Не пиши «готово», пока не запустил проверки и не увидел результат.
```

## Как шёл диалог

- **ИИ** заметил, что в шаблоне не заполнены поля, заполнил контекст сам из проекта (кто пользователи, тон, стек) и спросил одно — какой экран. **Человек:** «Весь кабинет».
- **Этап 1.** Refero MCP не был подключён; позже, когда автор его подключил, каждый запрос вернул `NO_SUBSCRIPTION`. ИИ **не стал выдумывать «результаты Refero»**: открыл в браузере документацию реальных продуктов (GOV.UK Design System, Linear Triage, Things 3, справка Apple) и прямо написал, что не получилось (две страницы не отрисовались, одна не открылась).
- **Честный аудит своей работы.** ИИ назвал 8 признаков «сделано ИИ» на экранах, которые сам и построил: кремовый фон с засечками и терракотой, карточки везде, одно скругление и одна тень на всём, цветные подписи над заголовками, метки статуса у каждой строки, «талон» в очереди, 3 обращения на экран сотрудника, одна фраза шесть раз подряд.
- Два направления, рекомендация. **Человек:** «А: «Ведомость»». Затем `DESIGN.md` с реестром решений. **Человек:** «Согласовано, начинай».
- На этапе 5 ИИ нашёл собственную ошибку: в медиазапросах ≥ 600 px остались правила прежней системы — увидел только на снимках широкого экрана.

## Что получилось

`DESIGN.md` (система «Ведомость» с источником у каждого решения), снимки «до» — серии `02–09`, «после» — `10`, команда `npm run demo:worst` для проверки худшими данными.
